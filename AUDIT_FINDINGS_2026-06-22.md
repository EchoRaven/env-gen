### [backend-projection] route_projector.py:498-769 (both)
- **file**: agent/env_generator/llm_generator/multi_agent/runtime/route_projector.py
- **problem**: The projector hard-codes a single-resource CRUD envelope: every business handler returns either {"item":{...}} (single) or {"items":[...],"total":N} (collection). There is no other response shape. This is reinforced system-wide: registryhub.py:273-283 OVERWRITES any non-item/items response_key, and delivery_gate.noncanonical_business_response_keys() (delivery_gate.py:409) hard-fails delivery on any response_key that isn't 'item'/'items'. So the contract is forcibly squeezed into one shape regardless of what the endpoint actually is.
- **fix**: Make the response envelope a contract-derived 'endpoint kind' rather than a global constant, but do it domain-agnostically and only where the contract DECLARES it (do not auto-guess media from path strings — that is itself a domain-shaped heuristic). Concretely: (1) Add an optional metadata.kind/response_kind vocabulary {collection, item, media, binary, aggregate, action, redirect, scalar} that a lane sets when registering a non-CRUD endpoint, defaulting to the existing item/items heuristic when absent — preserving today's behavior for the 95% CRUD case. (2) In route_projector._generate_handler, branch on that declared kind to emit the right shell: StreamingResponse/FileResponse for media/binary (returning a 501-or-empty valid stub when the lane left it unwired, NOT a JSON {item}), a plain dict for aggregate/scalar, RedirectResponse for redirect, and a {item}/{ok:true} for action. (3) In registryhub:273-283 and delivery_gate:409-463, STOP forcibly canonicalizing/hard-failing keys for endpoints carrying a declared non-CRUD kind; for declared CRUD endpoints keep today's item/items enforcement unchanged. (4) The single highest-leverage minimal step (matches the user's existing noncrud_envelope_map plan): widen the custom_route exemption story so a lane is reliably STEERED to register media/aggregate endpoints with custom_route=True + a non-CRUD kind, rather than the prompt only mentioning custom_routes.py for auth overrides. Verify on ONE live non-CRUD run (a video stream or analytics endpoint) before generalizing — do not build the full 8-kind taxonomy speculatively.
- **risk**: Loosening the canonicalization/hard-fail is the dangerous part: the item/items enforcement is NOT arbitrary — it is the documented fix for the single biggest blank-page source (frontend reading data.games against a {items:[...]} body) and for permanent remediation-less delivery blocks (smoke-notes 2026-06-19: GET/PUT/DELETE /api/notes/{id} got response_key='notes' → never delivered). If you relax the gate globally instead of per-declared-kind, you DROP that real protection: lanes that simply forgot to set item/items (the common mistake) will ship dead frontends again. The protection must be RE-EXPRESSED domain-agnostically, not removed — i.e. CRUD endpoints (no declared non-CRUD kind) keep strict item/items; only endpoints that POSITIVELY declare a media/aggregate/action/redirect/scalar kind are exempted and instead validated against THAT kind's expected shape. Two specific projector regressions that must survive any rewrite: the null-owner-on-create attribution (POST injects user.id into owner FK, route_projector.py:705-708) and the nested-route 500 protection (parent-resolve + scope_fk listing instead of Post.id==username string-vs-int compare, plus the /{username} non-id coercion at 588-603) — a kind-based refactor that re-routes GET/POST handlers must not lose these.
