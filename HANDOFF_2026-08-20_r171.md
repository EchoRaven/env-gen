## 0. The one thing to internalise first: the model is not the problem

**Model capability is sufficient. Every piece of evidence gathered today points away from it.**
If you arrive thinking "the agents can't write good code", you will spend hours optimising
prompts and lane instructions and find nothing, because that is what I did.

What the lanes actually produced, measured from artifacts:

- **r166 `LoginPage.jsx`, lane version, 612 bytes** — imported `AuthForm` and delegated to it.
  Correct, componentised, DRY. The framework replaced it with a 72-line inline copy of the same
  form, **46 times in one run**, because a byte-count heuristic read brevity as incompleteness.
- **r169 `LoginPage.jsx`, lane version, 51 bytes** — `export { default } from
  '../components/LoginPage';`. A one-line re-export, exactly right for a route entry whose
  implementation lives in a component. Overwritten by a 3960-byte inline page.
- **r167** — the lanes got the backend to **16/16 business probes passing, zero failures**, and
  the orchestrator fired `DELIVER_PROJECT` three times with substantive justification.
- **r164** — the lanes detected and closed **44 of 56 real defects** (six missing registered UI
  pages with their route wiring, breaking changes in two endpoints, a seed-data blocker, dead
  tables). r138, the run everyone points to as the success, detected **zero** and
  force-delivered past a failing check.

The lanes write correct code and then it is deleted, or a global they depend on never gets
defined. **The repair-task volume that looks like model failure is the cost of redoing work
that was already right.**

## 1. The actual blocker, diagnosed to root with evidence at every link

    11:36:06  GitOps Bot writes  services/api.js    3303 B, DEFINES window.NetflixAPI
              (the #638 shim checks for a same-stem sibling, finds none, correctly returns None,
               so a full baseline module is written)

    11:42:49  frontend writes    services/api.jsx   1457 B, does NOT define it
              (6m43s later — the collision forms AFTER detection already ran)

              App.jsx imports './services/api.jsx'  <- the one without the definition

    =>  window.NetflixAPI is undefined            (r171 log, 76 occurrences)
    =>  nine UI flows cannot run                  (r171 log, 45 occurrences)
    =>  validation_ui_evidence_failed + deliverability_ui_flow_failed never clear
    =>  the gate never settles
    =>  nine runs, zero deliveries

**The gap is not a missing solution.** `#638` measured this collision across **21 of 45
delivered frontends** (13 `.js`+`.jsx`, 6 `.js`+`.mjs`, 2 with all three) and noted the
framework's own `api.js` is one side of **every** one. `#632` names the resulting crash class.
`_reexport_shim_638()` implements the fix. `test_baseline_module_collision_638.py` guards it.

**What is missing is a re-check.** Gap-fill asks "does THIS FILENAME exist" (#638's own words),
so once `api.js` exists the shim is never re-evaluated — and the collision forms six minutes
later.

### Fix

- **Where:** `frontend_scaffold.py:11635`, the `_reexport_shim_638(p)` call site.
- **What:** when the file already exists, still check whether a same-stem sibling has since
  appeared and the current file is not a shim; if so, convert.
- **Constraint (#638, verbatim):** *"Skipping the write is NOT safe — projected code imports
  `../services/api.js` by [path]"*. So **`api.js` must stay the real module**; the later
  `.jsx`/`.mjs` is what becomes the re-export.
- **Test criterion:** `window.NetflixAPI` defined in the built app; the nine UI flows run;
  `validation_ui_evidence_failed` and `deliverability_ui_flow_failed` clear.

## 3. The retrieval rule — the most valuable thing I learned, the hard way

**This repo stores its conclusions in test filenames and log prose, not in implementation.**

For any *"why is this happening"* or *"should this behaviour change"* question:

    1.  ls agent/tests | grep -i <keyword>
    2.  grep the run log for the phenomenon in plain English
    3.  read implementation LAST

I did the reverse. **Seven passes of reading write sites and function names: 0 for 7.** One `ls`
found four items instantly. Things I re-derived that were already written down:

| Already existed | What it had | Cost of not finding it |
|---|---|---|
| `#910` | the clobber is deliberate, measured, test-locked | a day of rediscovery; `#1016` reverted for reversing it |
| `#914` | the deferral mechanism, its flag, a 42% corpus sample | I rewrote it worse (mine protected stubs too) |
| `#939` | the overwrite loop counted, "it is waste" stated outright | `sweep_write_conflicts` re-derived it |
| `#638` | the api collision, 21/45 runs, the fix constraint | **this is the actual blocker** |
| `#632` | the crash class the collision produces | — |
| `#794`/`#510`/`#553`/`restore_regressed_chains` | the business-chain side | — |

The framework also printed `set ENVGEN_DEFER_TO_LANE_PAGE=1` **595 times** in the log I was

## 4. Do not repeat these

- **`#1013`** — attached a guard to `scaffold_missing_local_pages`, which
  `Scaffolder.scaffold_frontend_pages()` **never calls**. A real guard on dead code. `LoginPage`
  went 64 → 92 alternations. Verify your fix is on the path that runs (`#1015`'s hash-diff
  instrumentation does this in one run; reading names does not).
- **`#1016`** — guarded the live write without knowing `#910` had deliberately decided the
  opposite, test-locked. Five failures, reverted.
- **`#995`** — a multi-site edit made without verification headroom: 10 failures, 3 errors, full
  rollback. **Three of today's reverts share that shape.** If you are low on context, record and
  stop.
- **n=1 conclusions** — I claimed a "90% cut" from one paired comparison, retracted it when
  r170 disagreed, then found the retraction was *itself* overcorrected (ranges are disjoint at
  n=5). State sample size and interval, never a point estimate.
- **Mid-flight readings** — three separate favourable readings at ~57 minutes were refuted by
  finals. Take finals only.

## 5. Tools you inherit (all selftested)

- **`tools/sweep_write_conflicts.py`** — finds files both sides commit to, and `_oscillates()`
  separates genuine clobbers from co-commits by looking for size reversals. Without that filter
  the numbers are ~2% inflated by benign co-commits; with it, r164 shows 18 real files / 1108
  alternations. `--selftest` pins both directions.
- **`tools/harvest_run.py`** — regression signatures per run, `--against <run>` for comparison.
- **`#1015`** (`framework_validation.py`) — hashes three target paths around
  `_scaffold_frontend_pages()`. **This is the pattern that works**: 35 hits in r167, 100% one
  file, after seven failed attempts to identify the writer by reading. Copy it when attribution
  is unclear.
- **`#1014`** (`heal_pipeline.py`) — logs every lane-owned path the bulk delivery phase commits.
  Collapsed 23 candidate functions to 3 files in one run.
- **`#1009`/`#1017`** — make `incomplete_required_tasks` and `validation_ui_evidence_failed`
  name their instances instead of just failing. Both landed, **neither verified by a run yet**.

## 8. Honest caveat

I peeled four layers today, and each looked like bedrock:

    "the model can't fix bugs"  ->  the framework overwrites its work
    "it's the overwrites"       ->  UI evidence can't be collected
    "it's evidence persistence" ->  a JS global is undefined
    "the fix doesn't exist"     ->  it exists; it just never re-runs

I cannot promise there is no fifth. What I can say is that layer four is diagnosed with a
timestamp on every link, the fix point is a single line, and the constraint is written down by
the person who measured the problem two hundred items ago.

**And at no point in four layers did the evidence implicate the model.**
