# 2.2: Qwen3.8-27B + Codex vs Claude Code — Netflix Benchmark

Replication of experiments 2 (`../2_thb_netflix_selfval`, oracle observable) and 2.1
(`../2.1_thb_netflix_oracle_hidden`, oracle hidden). The single Claude Code worker is replaced by Codex CLI driving
a local Qwen3.8-27B. The benchmark (frozen `benchmarks/env-gen`), task prompts, contract, validator, dev evaluator, and
hidden evaluator are unchanged. Wrapper changes are listed under "Issues". 20 iterations per job (Claude ran 5).

## Setup
- **Model:** RedHatAI/Qwen3.8-27B-INT4 on local vLLM (one RTX 6000 Ada, 48 GB). FP8 KV cache,
  `max-model-len 262144` (native), max-num-seqs 8, qwen3 reasoning parser, qwen3_xml tool parser
  (`scripts/vllm_exec.sh`, user unit `shabi-forest-qwen-2-2.service`). About 35-38 tok/s generation, 85-97% prefix-cache hits.
- **Agent:** Codex CLI 0.163.0 (`codex exec` / `exec resume` in one session per job), reasoning effort medium.
  The model catalog declares the 262,144-token window, with auto-compaction at 220,000 tokens (`common/codex.json`).
- **Context:** 262K tokens. Compaction works in real sessions: job 1 compacted 11 times and job 2 twice, with no
  failed turns and no abandoned sessions. Smoke tests: a 199,889-token turn, plus a forced compaction followed by resume (`smoke/`).
- **Sandbox:** bwrap (`common/codex_worker.py`). It has an empty root, read-only system paths, and the workspace as
  the only writable project path. Job 1 adds `/thb`, `validate`, and `/validate_io` as in experiment 2; job 2 adds only
  Node and the design materials. Checked: the project tree and `~/.claude` are invisible, and `/etc` is read-only.
- **Iterations:** 20 per job, with a 4 h timeout each (never reached). Job 1 ran 02:13-14:37 and job 2 ran 14:38-18:20
  on 2026-11-05.
- **Hidden visual judge:** Claude Opus 5.5, 3 judgments per screen as in 2.1, run on the acct2 OAuth token in an
  isolated home (`common/claude_judge.py`).

## Results

Static audit (H2, every hidden-evaluated snapshot of both jobs): no detector fired (no parked probe routes, stub

### What the numbers say
- **Job 1 (oracle observable).** All 20 official validations pass. Endpoints went from 12/15 (it1) to 13/15
  (it2-14) to 15/15 (it15-20). The hidden evaluation does not follow that rise:
  - Hidden API slips from 47/49 (it1) to 46 (it4-13) and then 42-43 (it16, it20). At it20, removing from My List
    and 4xx validation for bad My List/profile input fail.
  - Visual similarity drifts down from 0.542 to 0.507 (it12).
  - **it13 shipped a frontend crash** (`ReferenceError: seasons is not defined`; every page after sign-in is blank:
    UI 6/22, visual 0.298). The agent's own validator gave it 14/14, because api_smoke checks routes and the API,
    not rendering. A later iteration fixed it.
  - **From it14 the hidden UI walk cannot sign in.** Qwen rebuilt the login as Netflix's two-step form (email →
    Continue → password) to match the reference. 2.1's frozen walk and capture expect a password field on the first
    screen, so they time out (UI "walk did not crash" fails; visual capture errors on it16 and it20). A person can sign
    in (verified below). This is a limitation of the evaluator. The instrument was left unchanged for comparability.
- **Job 2 (oracle hidden).**
  - it1 did not boot (the database container exited with code 3).
  - it2 published host port 8000, which the vLLM server occupies, so dev docker_up failed. The agent moved to
    48000 in it3. Job 1's agent hit the same clash on its first `validate` call.
  - From it3 the dev evaluator shows 14/14, chain 8/8, 11/15 endpoints. Claude in 2.1 also stayed at 11/15 on this
    dev evaluator, so 11 looks like its ceiling.
  - The hidden scores are flat from it2 to it20: API 46/49 (rating and re-rating fail, plus one 4xx validation
    case), UI 22/23, visual ≈0.52-0.53.
  - After it2 the agent spent only 2-14 min per iteration (3.3 h in total vs 12.3 h for job 1) and made small
    changes.
- **Observable vs hidden, for Qwen.** The visible oracle bought endpoint coverage (15 vs 11 on the respective
  oracle) and more work, but no hidden gain. Job 1's hidden API and UI scores ended lower than job 2's, and it shipped
  one fully broken frontend (it13) that its oracle passed. Job 2's hidden scores were steadier. Visual scores are
  similar (≈0.51-0.54 for both). This matches 2.1's conclusion for Claude: seeing the dev oracle does not improve
  hidden quality. Here it also encouraged regressions the oracle cannot see.

## Visual Evaluation

Each job's final iteration was booted (`job_selfval/scripts/view.py 20`, `job_oracle_hidden/scripts/stack.py view 20`)
and driven through its real UI by `common/tour.py`. The tour registers a fresh account, signs in through the visible
form, picks a profile, opens all header links, hovers and opens a card, and presses Play. Screens, a contact sheet,
and notes are in `job_selfval/results/tour/it20/` and `job_oracle_hidden/results/tour/it20/`. They are compared with
`benchmarks/env-gen/design_inputs/netflix/references/`.

- **Both** are recognisably Netflix:
  - #141414 theme, red NETFLIX wordmark, the reference's nav items, and a full-bleed hero billboard with Play / More Info;
  - poster rails with real catalog posters, Top-10 numerals on New & Popular, and hover preview cards with
    play/add/rate controls;
  - honest empty states and no console errors.

  Both differ from the reference in the same ways: the hero is full-bleed with plain title text, where the reference
  has an inset rounded card with a title-logo image; buttons are square, not pill-shaped; profile tiles are plain, not
  the provided avatar art. Video playback could not be verified: the clips are served (200, video/mp4), but
  Playwright's Chromium lacks H.264.
- **Job 1 it20.**
  - Works: two-step sign-in, landing with a poster collage, a title page with genres and "#1 in TV Shows" and
    "Recently Added" side rails.
  - **Defect:** the title page's Play button overlaps the metadata line and is covered by another layer. A real
    click does nothing, so the player is reachable only by URL.
  - A TV title says "No episodes for this title yet".
  - The Games page presents movies as "Play Game" items. The dataset has no games, so this is closer to fabricated data.
- **Job 2 it20.**
  - Works:
    - Play works from the hero and the hover card, and opens a player with a full control bar.
    - Browse by Languages has the reference's Original / Dubbing / Subtitles filters.
    - Home has a Continue Watching rail (empty state), and there is a search page.
    - Games shows honest "no games" rails.
  - Defects:
    - One title's poster renders as a broken white tile in several rails.
    - Sign-in is a one-step form.
    - There is no separate title-detail view (the hover preview stands in).
- **Overall:** comparable fidelity. Job 1's final app has the more Netflix-like flows. Job 2's is more usable
  end to end (Play works) and more honest (Games), and it scores better with the hidden UI walk and API.

- **On the automated checks the agents match Qwen.** Both reach the same api_smoke results; Qwen even reaches
  15/15 endpoints with the visible oracle.
- **The hidden evaluation separates them.** Claude passes every hidden API and UI check from iteration 1. Qwen
  stays at 46/49 (ratings never work) and 22/23 at best, and scores about 0.2 lower on visual similarity (0.53 vs
  0.74). The largest visual gaps are the player (0.05 in job 1, where the hidden capture cannot start playback) and
  the login and genre screens.
- **Qwen does not converge to Claude's level with 4x the iterations.** Hidden scores plateau after iteration 2-4.
  With the oracle visible, Qwen keeps changing the app, and it regresses hidden behaviour twice (it13 crash, it20 My List
  removal) while its own oracle stays green.
- **Cost.** Claude finished in 5 iterations taking about 1 h of agent time. Qwen used 12.3 h + 3.3 h of local GPU
  time: job 1's session used 150M input tokens (96% cached) and 1.5M output tokens; job 2 used 48M and 0.42M.

## Issues and Observations

Infrastructure and wrapper changes (none touch what is tested):
1. `sg docker` cannot run inside the proctor's sandbox, and docker is reachable directly. `codex_worker.docker_argv()`
   falls back to `sg` only when needed.
2. The visual judge in 2.1 bound the user's real `~/.claude`. In 2.2 it uses an isolated home with the acct2 OAuth
   token (`common/claude_judge.py`) and the same binary, model, prompt, and tools.
3. Qwen publishes its backend on 48000, and 2.1's +20000 hidden port offset overflows 65535. `stack.py` wraps only an
   overflowing port into range. Qwen also copied the read-only design assets with their modes, so re-staging failed.
   `make_writable()` runs before staging.
4. Compose project names were made 2.2-specific (`thbhid22`, `thbview22-*`). `validator.py` (unchanged) still uses
   `thbval`.
5. **Judge quota.** The judge shares the acct2 subscription with the proctor. It hit the session limit during job 2,
   and those judgments came back as "You've hit your session limit" (recorded as missing, never as 0). They were
   re-judged from the saved captures after the limit reset (`job_oracle_hidden/scripts/rejudge.py`,
   `scripts/rejudge_loop.sh`); the "visual re-judged" note marks them.
6. **Container-name clash (confound).** Qwen's compose hard-codes `container_name: netflix_*`. In job 2, iteration 12's
   dev stack collided with the still-running hidden stack of iteration 11, so the agent was shown a false docker_up
   failure for it12. A post-hoc rescore of that snapshot passes 14/14 with chain 8/8. From iteration 15 the dev evaluation also
   holds the hidden-stack lock, and job 2 was restarted once (17:29) to load this. Job 1 had two `validate` calls
   fail on host-port clashes: port 8000 held by vLLM at it1 (genuine), and 48000 at it13 (source not identified).

Codex + Qwen behaviour:
- **Stability.** The local stack was stable for about 16 hours: no vLLM restarts, no failed or retried Codex turns (one turn, job 2 it15, was interrupted by the proctor's restart and resumed), no
  context overflows, and correct tool-call parsing throughout.
- **Diminishing effort.** After a long first iteration (~65 min), iterations shrank, especially in job 2 and in job 1
  after it15 (1-5 min, often just one `validate` call and a submission). The model treats a green oracle as done.
  It rarely explores unverified features (ratings never got fixed in either job).
- **Changes the oracle cannot see.** With the visible oracle, Qwen made more ambitious UI changes (two-step
  login, collage landing) that improve resemblance. It also broke things the oracle cannot see (it13 crash, covered Play
  button, My List removal at it20).
- **Port collision.** Both agents first published the backend on host port 8000, the vLLM server's port. In job 1
  the agent learned this from `validate`; in job 2 from the dev report.
